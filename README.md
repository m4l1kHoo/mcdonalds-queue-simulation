# 麦当劳排队仿真课程项目

从历史观测表重新建立数据处理、输入分析和排队仿真实验。项目作者在原课程项目中主要负责数据采集和 AnyLogic 建模。本仓库交付本次新增的 Python 参考模型及分析流程，不将原团队的全部工作归为个人成果。

本次新增了可追溯的数据提取、统计诊断、Python 离散事件参考模型、测试和结果报告。**Python 流程已完成端到端验证；与原 AnyLogic 模型的运行等价性尚未验证。** 历史报告中的改善百分比不作为新版已验证结论。新增代码与文档在 AI 工具辅助下完成，原课程贡献与本次重建分别记录。

先看 [已运行的结果摘要](docs/results/README.md)、[方法与假设](docs/methods.md) 和 [验证记录](docs/validation.md)。Python 部分不依赖 AnyLogic 安装；本次 Git 提交不包含原 ALP 或未验证的修订候选。

## 快速运行

需要 Python 3.13。以下版本已在 Python 3.13.5 验证；其他 Python 版本尚未测试。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -B run.py --smoke --output results/smoke
python -B run.py --output results/rebuild
```

打开 `results/rebuild/report.html`。完整运行默认使用种子 20261016、每情景 100 次、6 个情景，共 600 次参考仿真；输入分析的部分诊断使用 199 次重新拟合自助重复。小规模运行仅每情景 3 次，不计算自助 p 值。

输出目录必须是新目录或空目录，避免把不同轮次结果混在一起。重复执行时换一个 `--output`，例如 `results/rebuild-2`。运行会先执行测试；任何测试失败即停止后续实验。运行不需要网络，不访问原项目目录，也不会启动旧 Notebook。

实际验证的环境和范围记录在 [验证记录](docs/validation.md)。版本文件锁定直接依赖；当前没有声称完成所有操作系统的验证。

## 输入从哪里来

- `data/observations.csv`：18 组分开标记的数据，共 753 条记录，保留原值、单位、状态、工作簿/Notebook 和单元格来源。不同组之间可能对应同一批观测，不表示统计独立。
- `data/arrivals.csv`：周六观察表的 56 组到达事件，保留同行人数、外卖员标记及缺失状态。它不是 56 名独立顾客。
- `data/reconciliation.json`：Notebook 与工作簿之间的对应及差异。
- `data/source_structure.json`：7 个工作簿的全部工作表结构、非空单元格数和公式位置。它是覆盖记录，不表示每个字段都被选为模型输入。
- `docs/source_manifest.json`：原目录 17 个文件的大小与 SHA-256，包括未纳入计算的报告和 Finder 元数据。

原始 Excel 和 Notebook 的本地副本位于 `private_originals/`，不随仓库上传，包含历史署名等信息。原始目录保持不变。仓库复现使用已提取的数据；标准化文件去除了观察者姓名、订单编号和自由文本，保留技术来源位置。普通运行从标准化数据开始；重新提取原始单元格需要另行持有原始工作簿和 Notebook。

若拥有原始副本，可以重新生成标准化数据：

```bash
python -B prepare.py --source private_originals --output data
python -B run.py --from-originals --output results/from-originals
```

提取前会核对源文件哈希。输入分析和仿真也会核对标准化数据清单，数据发生变化时需要明确重建其版本。源表不被保存、重算或修改。

## 完整使用流程

| 步骤 | 程序 | 输入 | 输出与检查 |
| --- | --- | --- | --- |
| 数据准备 | `prepare.py` | 原工作簿、Notebook JSON | 标准化观察、到达记录、来源映射与异常状态；不执行 Notebook |
| 输入分析 | `analyze.py` | `data/` | 有效样本基线、IQR 敏感性、拟合参数、原序列 ACF、有限 Q–Q 图 |
| 参考仿真 | `simulate.py` | `data/`、`config.json` | 六个情景逐次结果、首次重复的逐组/事件日志、配对差异区间 |
| 报告 | `run.py`、`report.py` | 上述结果与实际环境 | HTML 报告、测试记录、代码和输入哈希 |

各步骤也可独立运行：

```bash
python -B analyze.py --output results/input
python -B simulate.py --output results/simulation
python -B -m pytest -q -p no:cacheprovider
```

## 数据和模型的关键选择

1. **单位有明确来源。** 用户于 2026-10-16 确认数值分钟使用十进制表示：1.30 分钟为 78 秒。表头明确为秒的列不乘以 60；Excel 日小数、时间戳和 `8min8s` 文本分别处理。
2. **基线保留有效长尾。** IQR 规则仅标记和建立敏感性情景，不认定被标记的记录错误。负时长、跨日冲突和缺失值保留在数据中，状态不同于有效长尾。
3. **不混合不同事件边界。** 订单到完成、叫号到取餐、取餐到离开和就餐时间各自独立。旧 Notebook 的第二组 52 条“完成时间”不与第一组 66 条混合；其中前三条与原表负间隔不一致。
4. **默认仿真使用经验样本。** 基线机器操作时间来自周六表中 8 条明确标为秒的记录。旧 Notebook 的 45 条十进制分钟样本作为独立敏感性情景。参数分布拟合是诊断，不自动成为“最佳”输入。
5. **参考模型有新增假设。** 一组对应一单，整组占座，先取餐后占座，初始系统为空；缺失同行人数暂按 1 人；未记录的点单方式和堂食意图使用显式暂定概率。没有证据支持的耐心分布不自动启用。
6. **统计完整入场群体。** 到达窗口是 `[0,3600)` 秒，结束时记录未完成者，之后排空。系统逗留包含就餐，不能把它叫作排队等待。所有均值的分母及条件均可在日志追溯。

详细数学定义和局限见 [方法说明](docs/methods.md)，新旧对应关系见 [变化记录](docs/changes.md)。

## 与原 AnyLogic 项目的关系

原 8.9.2 模型和修订候选保留在本地，暂不纳入此仓库。原模型包含满座分流、提前占座、条件概率和超时等尚未澄清的路径。Python 参考模型采用明确说明的流程，目前没有与原模型做等价测试，也不依赖原 ALP 才能运行。

## 结果能支持什么

结果可以检查代码、样本处理、资源约束和给定假设下的实验差异。100 次重复的区间只反映固定数据和假设下的 Monte Carlo 变化，未包含输入抽样不确定性。订单完成时间存在明显序列相关，独立经验抽样没有保留它。不同日期的输入也不能支持跨时段预测。

结果尚不足以支持真实门店的最优配置或旧报告的改进幅度。本仓库定位为可检查、可复现的课程项目重建。当前未附加通用开源许可证，也未替原团队材料授予额外许可。
